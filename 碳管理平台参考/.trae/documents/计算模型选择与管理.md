# 计算模型选择与管理 实施方案

## Context

当前【碳足迹核算】页面的"核算参数"区域硬编码了光伏专用的 6 阶段（`TRAIN_ACC_STAGES`）和光伏专用碳足迹公式（`computeTrainCfp`，公式1），以及光伏专用额外参数（`directSupplyKwh`/`lineLossRate`）。这使得该模块只能用于光伏发电产品。

用户希望：
1. 在【碳足迹核算】详情页"核算参数"区域之前增加"计算模型"选择，选择后核算参数/公式自动关联对应模型。
2. 新增"计算模型管理"页面，展示内置计算模型（光伏/风力等），供调用参考。

经确认：计算模型管理**仅展示内置模型（只读）**；风力公式**先用占位**，稍后由业务方补充；计算模型与现有"碳足迹模型（因子库 trainModels）"是**独立概念**但互相关联（产品同时绑定两者）。

### 计算策略分发

新增 `computeCfp(acc)` 分发器（L4105 附近，紧邻现有 `computeTrainCfp`）：
```js
function computeCfp(acc) {
    const code = acc.calcModelCode || 'CALC-PV-01';
    const model = CALC_MODELS.find(m => m.code === code) || CALC_MODELS[0];
    switch (model.calcMethod) {
        case 'pv': return computeTrainCfp(acc);   // 复用现有
        case 'wind': return computeTrainCfp(acc);  // 占位：暂用光伏公式，待业务方补充
        default: return computeTrainCfp(acc);
    }
}
```
报告中所有 `computeTrainCfp(acc)` 调用点改为 `computeCfp(acc)`（约 3-4 处）。

### 产品（acc）数据结构扩展

`normalizeTrainAcc`（L4122）增加：
```js
if (!acc.calcModelCode) acc.calcModelCode = 'CALC-PV-01';
```
旧产品默认关联光伏计算模型，向后兼容。

### 核算详情页改造

修改 `renderTrainAccountingDetail`（L4573），在"产品基本信息"卡片之后、"核算参数"卡片之前插入**计算模型选择卡片**：

```
┌─ 计算模型 ─────────────────────────┐
│ 计算模型: [光伏发电系统计算模型 ▼]  │
│ 功能单位: 1 kW·h 上网电量          │
│ 计算公式: CFP_pv = (Em_rs+...)/...  │
│ 引用标准: GB/T 24067-2024 ...      │
│ 说明: ...                           │
│ [查看模型详情] →                    │
└────────────────────────────────────┘
```

- 下拉框选项来自 `CALC_MODELS`
- 选中后：`acc.calcModelCode` 更新并 `saveTrainAccs()`
- 下方"核算参数"区域的 `STAGE_INPUTS` 和 `CFP_INPUTS` 从所选模型动态生成：
  - `STAGE_INPUTS` = `model.stages.map(...)`
  - `CFP_INPUTS` = `model.extraParams`
- 阶段排放量输入框、额外参数输入框都用动态数据，不再硬编码光伏字段

### 计算模型管理页面

新增函数 `renderCalcModelManage(container)`：
- 落地页风格（类似 `renderProductCarbonModelTrain` L1178 / `renderTrainReportHome` L5958）
- 卡片网格列出所有 `CALC_MODELS`，点击进入详情
- 详情页 `renderCalcModelDetail(container, code)` 展示：
  - 基本信息（编码/名称/产品类型/功能单位/引用标准/说明）
  - 阶段列表（表格：阶段名称 / 公式 / 结果单位）
  - 计算公式（文字）
  - 模型专用参数（表格：参数名/单位/默认值）

- `computeTrainCfp`（L4105）：光伏公式实现，`computeCfp` 分发后复用
- `renderProductCarbonModelTrain`（L1178）/ `renderTrainReportHome`（L5958）：落地页布局模板
- `renderTrainModelDefinition`（L1398 附近）：详情页布局参考
- `el(tag,attrs,children)` DOM 构造器、`navigate(hash)` 路由跳转、`saveTrainAccs()` 持久化
