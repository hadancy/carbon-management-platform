## 1. 报告流程与边界

- 报告必须从本校 **核算审核通过的正式运行** 创建，包括保留的历史通过版本；试算、未经审核的运行和其他学校的运行均不可使用。
- `FootprintReport` 固定学校、运行 ID、来源快照及模板版本。来源记录学校与项目、核算审核、模型、规则、因子、活动输入、年度电量、证据摘要和精确结果。
- `ReportRevision` 只接受标题、编制人、日期、目的、方法、数据质量、结论和限制等说明字段；请求白名单拒绝传入结果或来源快照。
- 草稿允许不完整保存；前端字段级 rules 和服务端完整性检查同时控制提交。正文版本和修订 ID 用于并发与旧目标拦截。
- 状态为 `DRAFT → SUBMITTED → APPROVED / REJECTED`。提交后正文冻结；通过或驳回只能创建新修订，原版、审核意见和 PDF 保留。
- 创建人、最后编辑人或提交人不得自审，学校管理员同样受限。审核意见必填。
- 所有校内角色可读取本校报告；编辑、审核、导出按既有角色矩阵授权。跨校页面、详情、预览、PDF 生成与下载均重新校验。
- HTML 预览和 PDF 使用同一结构化文档和同一 HTML 模板。正式 PDF 只允许通过审核的修订生成，历史通过版本仍可下载。
- 导出在阻断网络的 Chromium 中嵌入 Noto 简体中文开放字体；A4 页眉、页码、重复表头及长文自动分页。报告文字先转义，预览 CSP 禁止脚本执行。
- 每个审核修订仅保存一个 `ReportExport`。并发生成、重复点击及重试复用同一文件；内容摘要和 PDF 字节摘要复核后才能下载，并写入导出及下载审计。
- 内置工程模板当前为 `pv-report-1.0.1`；`1.0.0` 保留兼容渲染，已有导出不改写。新版明确列出输配电后电量这一足迹分母，并按 America/New_York 展示审核时刻。
- 公共资料中的任意 `REPORT_TEMPLATE` JSON 不直接作为 HTML 执行。本轮使用受版本控制的内置工程模板；业务模板确认与受控映射作为正式启用前的配置工作。

## 4. 模块职责

页面负责装配和权限；报告列表、筛选、表格、创建弹窗、正文表单、审核弹窗、来源卡片、预览及客户端流程分别维护。服务端分为来源快照、查询、草稿/修订、审核、渲染装配、PDF 引擎和持久导出；纯文档与 HTML 模板不依赖数据库。复用现有角色权限、校内证据下载、认证、审计、请求反馈和未保存离开提醒。

报告新增模块遵守单一职责。原 `accounting-editor.tsx` 仍将核算流程、历史表格和审核弹窗组合在一起，本次只增加生成报告入口；这些既有区域后续仍可进一步抽离。
