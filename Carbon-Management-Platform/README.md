## 本地启动

需要 Node 24、npm 和 Docker。项目的 `.nvmrc` 指定 Node 24。

```bash
nvm use
npm ci
cp .env.example .env
```

修改 `.env` 中的 `POSTGRES_PASSWORD`，同步修改 `DATABASE_URL` 中的密码，并将 `BETTER_AUTH_SECRET` 改成至少 32 字符的随机密钥。`BETTER_AUTH_URL` 设置主要访问地址，默认是 `http://localhost:3000`；其他登录地址通过 `BETTER_AUTH_TRUSTED_ORIGINS` 显式配置。随后运行：

```bash


# 启动 Docker 运行环境
colima start

# 启动数据库并等待就绪
docker compose up -d --wait

# 更新数据库结构并生成客户端
npm run db:deploy
npm run db:generate

# 启动项目
npm run dev



docker compose up -d
npm run db:deploy
npm run db:generate
npm run bootstrap:admin -- --email admin@example.com --name 平台管理员
npm run dev
```

首次创建平台管理员时，命令会交互式询问密码，并为该账号写入平台超级管理员角色。打开 [http://localhost:3000/login](http://localhost:3000/login) 登录，然后在“系统管理”中创建学校、学校账号、公共数据版本及公用模型模板。管理员若没有学校成员身份，只能进入系统管理；需要进入学校工作台时，应为其显式分配学校归属。

局域网访问时，在 `.env` 中加入 `BETTER_AUTH_TRUSTED_ORIGINS=http://192.168.1.29:3000`，将示例 IP 替换为运行服务电脑的实际局域网 IP，并重启开发服务。多个额外地址用英文逗号分隔，不加空格，每个地址包含协议、主机和端口，不带路径或末尾斜杠。保留 `BETTER_AUTH_URL=http://localhost:3000` 时，本机与所列局域网地址均可登录；电脑 IP 变化后须同步更新此配置。

`next.config.ts` 复用上述主要地址和额外来源，将主机名填入 Next.js 的 `allowedDevOrigins`，允许对应地址加载开发资源和连接热更新。该配置仅影响开发服务，认证仍按完整来源校验。

若登录接口返回 `403 INVALID_ORIGIN`，表示当前访问地址尚未被信任；登录页目前会将认证失败统一显示为账号、密码或停用提示，应先检查来源配置。

本地 PostgreSQL 仅绑定 `127.0.0.1:5432`，数据保存在 Docker 命名卷 `postgres_data`。`docker compose down` 保留数据卷；`docker compose down -v` 删除数据卷。

## 已实现的管理流程

- 平台超级管理员在“学校与账号”工作区按学校管理成员，或在全部账号视图管理跨校归属；可创建、启停学校和账号、添加或移除学校归属、重置密码，并删除非平台管理员账号。删除会移除登录凭据和学校归属，保留匿名记录供历史审计与资料引用。
- 用户使用邮箱密码登录、退出、修改密码，并在已授权学校之间切换。账号停用或密码重置会使原有会话失效。
- 平台管理员创建和编辑公共数据草稿，发布排放因子、规则配置和报告模板版本。公用排放因子 v2 用数值、活动单位、用途、适用范围和来源表单录入，界面自动展示 `kgCO₂e/活动单位`；发布前校验完整性。旧版本可复制为新草稿补齐 v2 字段，已发布内容冻结，停用只记录元数据和审计。学校用户可读取已发布版本。
- 服务端检查每次管理请求和学校上下文，记录学校、账号、成员关系及公共数据关键变更的操作者和时间。

校内角色权限矩阵已在模型、核算和报告接口落实。核算服务固定模型、规则、因子、活动输入、证据摘要和引擎版本，输入改动后须重新计算。

## 公共数据项库

平台管理员在“系统管理 → 数据项库”（`/admin/data-items`）统一维护数据项。主表按编码一项一行并分页，显示当前发布版和草稿。可以按名称、编码、规格、厂家、状态和单位筛选，命中任一版本即可找到其数据项。通过“历史版本”可按版本号倒序查看原有因子、停用原因和引用记录。普通学校用户无管理权限。

- 新建时填写唯一编码和数据名称，先保存 v1 草稿；活动单位可暂缺，发布前必须选择目录中的单位。排放因子只填有限数值，因子单位自动生成，原始资料和来源字段保留。
- 草稿可编辑。发布操作同时校验并保存表单，成功后内容只读。更新已发布内容时选择“创建新版本”，系统自动分配下一版本号。新版草稿期间仍可选用原发布版。正式发布后仅新版可选，系统自动删除同一数据项中从未被引用的旧发布版，曾被引用的版本停用后保留。每个数据项最多一份未发布草稿，多人同时编辑通过修订号防止覆盖。
- 已发布版本可填写原因后停用，停用保留内容、发布时间和审计历史。编码唯一；同名但不同规格、厂家或单位的数据项可使用不同编码维护。
- 删除以当前版本为单位：草稿及从未被引用的已发布版本允许删除；已被模型引用（含历史、归档及后续移除/删除草稿的引用）的版本只能停用。列表展示引用记录并禁用已引用版本的删除按钮；服务端重新检查修订号、引用及并发状态，阻止过期页面误删。
- 成功删除保留操作者、时间、编码、版本和完整资料快照审计。新版发布、模型同步与自动清理在同一事务中完成。同一数据项的已删除版本号不会复用。手动删除最后一份未引用版本时同时移除空数据项，编码可用于重新新建。增量迁移从模型、固定核算及报告来源回填引用。
- 模型编辑页面通过“从公共库选择”搜索每个数据项当前的可用发布版本，支持名称、编码、规格、厂家和单位筛选、跨页多选以及更换版本。公共资料只读，同一大类内不能重复选用同一个数据项。当前版本停用后，该数据项等待下次发布才可重新选用。
- 公共数据项新版发布时同步关联的公用模板和各校模型。单位与其他资料一致时，草稿会自动更新排放因子及只含数值和单位的原始碳足迹因子。单位、来源或可能影响计算边界的内容变化时，编辑者核对并选用新版后再提交或发布。
- 已发布模型和模板以新版草稿承接公共数据项变更。待审核的本校版本按送审内容完成审核，通过后生成新版草稿，驳回后按草稿规则处理。已有数据项可用 `npm run data-items:sync -- 数据项编码 [平台管理员邮箱]` 补同步。存在多名有效平台管理员时须指定邮箱。
- 每次选用保存公共数据项身份、所选版本与完整资料快照，并生成模型内独立标识。更换时保留该标识以兼容计算映射。已发布的模型和模板、核算和报告按各自快照追溯，新选用由服务端验证资料和版本状态。
- 旧模型自有数据标记为“旧模型自有数据”，可原样保留、移除或更换为公共库版本，兼容已识别的旧单位和带单位因子归一。不允许通过模型接口新建自有数据或改写公共资料。学校 A 中 15 个既有自建模型的 258 项资料已按用户要求整理并发布入库，保留原字段、因子空缺及逐项来源；详见 [2026-10-29 入库记录](docs/2026-10-29学校A自建模型数据项入库记录.md)。其他学校资料不会自动发布为公共数据。

本地更新后运行 `npm run db:deploy` 和 `npm run db:generate`，并重新启动应用以载入新的 Prisma Client。`npm run test:integration` 使用独立临时库验证权限、发布、并发覆盖、新版本、停用、搜索、分页及浏览器操作，测试资料不会写入开发数据库。

## 碳足迹模型

- 平台管理员在“公用模型模板”维护并发布版本，所有学校可查看已发布版本。学校从指定模板版本创建本校草稿时复制结构、保留模板来源版本，并带入关联公共数据项的可用新版。学校独立维护生成的模型。
- 有模型编辑权限的校内用户可自行创建模型并维护阶段、大类，从公共库搜索选用数据项；模型保留编码、名称、功能单位数量与单位、系统边界及示意图、引用标准、说明，以及所选数据项的规格、厂家、单位、因子和来源快照。数据项内容由平台管理员统一维护，模型中可更换、排序或移除。原型示例数值不作为正式因子导入。
- 本校模型提交后由有模型发布权限的校内角色审核，可驳回或发布；创建人、最后编辑人和提交人均不得审核该版本。发布版本只读，后续修改从发布版本创建新草稿。
- 草稿编辑的必填字段使用表单 rules 给出字段级提示；未完成内容仍可保存草稿，提交审核或发布时必须校验通过。
- 模型列表的编辑/查看进入独立版本子页面；新建模型或新版本后直接进入该页面。学校用户可在本校页面只读查看已发布的公用模板。
- 模型列表提供删除操作。删除会归档模型、从列表移除并允许重新使用该编码；历史版本和已复制到学校的副本保留。已发布的本校模型须由拥有模型发布权限的校内成员删除，公用模板由平台管理员删除。
- 示意图首期作为不超过 2 MB 的 PNG/JPG/WebP 存于模型版本快照；后续文件存储接入时可迁移到对象存储。模型可显式配置光伏五阶段计算映射；原有自由文本因子字段仍是资料，不会代替公用因子 v2 的版本引用。

## 光伏计算内核（T01～T03）

`src/domain/calculation/pv.ts` 导出 `calculatePv(input)`：传入本校已发布模型版本及其稳定 ID 映射、公用因子 v2 版本快照、逐项活动数据、完整年度电量、线损比例和并网简化法依据，返回五阶段排放、总上网电量、每度电碳足迹及字段级诊断。输入数值使用十进制字符串，展示值单独舍入；`estimateAnnualEnergy` 可生成缺少实测值年份的显式清单。独立测试 `npm test` 中的 `SYN-PV-001` 验证结果为 `0.062947 kgCO2e/kWh`。这些测试数据标记为 TEST，不构成正式业务案例或标准符合性结论。

## 碳足迹核算（T04～T05）

- 学校用户在“碳足迹核算”中从本校已发布模型创建案例，逐项录入活动量和年度电量，保存草稿并运行并网光伏试算。模型数据项已有的数值因子可直接用于 **试算**，不必在公共数据重复录入；试算因子与输入一并固定在运行快照中。
- 正式计算须选择已发布的公用因子 v2 与规则版本，上传活动数据和年度电量凭证。模型内因子尚缺完整的地区、期间和授权信息，因此暂不能代替正式因子版本；正式业务启用还需 B01～B06 的方法确认和真实手算样例。
- 并网正式规则版本内容使用 `schemaVersion=1`、`purpose=PRODUCTION`、`product=PV`、`scenario=GRID_ONLY`、`formula=PV_GRID_V1`，并填写 `standardReference`、`effectiveFrom`、`effectiveTo`、`approvalReference`；这些依据须由业务方确认。正式案例还须填写规格、项目地点、采集期间、系统边界及取舍说明；首版只接受明确无取舍项的案例。
- 每次计算生成只追加的运行记录；相同请求标识和相同输入返回原运行，不同输入会冲突。保存草稿使用输入版本防止覆盖，旧运行和已审核修订保留。创建人、最后编辑人和提交人均不得审核自己的修订。
- 附件支持不超过 5 MB 的 PDF、PNG、JPG、WebP，按学校授权下载。临时数据库集成测试覆盖两校试算、跨校案例与附件拦截、正式运行、审核、重复请求和旧结果冻结。

## 碳足迹报告

- 在核算页选择“生成报告”，或在报告列表选择核算审核通过的运行。历史通过版本仍可用；试算及跨校运行不能创建报告。
- 编辑标题、日期、方法、来源、结论等说明。可以保存未完成草稿，提交前须通过前端和服务端校验；正文请求不能改写核算数值。
- 创建人、最后编辑人、提交人不得自审；独立审核员填写意见后通过或驳回。通过/驳回后创建新修订，保留原版本、审核记录与 PDF。
- 报告预览和 PDF 使用同一结构化文档和 HTML 模板；导出只接受审核通过的修订。PDF 嵌入中文字体，固定模板版本，并保存唯一导出及文件摘要。重复请求返回相同 PDF；详情、预览、生成、下载和证据附件均执行本校授权。
- `npm run demo:reports` 为已有 `DEMO_PV_001` 的已审核运行创建或核对 `DEMO_REPORT_T07`：v1 驳回、v2 通过并导出、v3 草稿继续体验。演示登录和七页 PDF 样张见 [T07 验收记录](docs/T07报告验收记录.md)。
- 内置工程模板已升级到 `pv-report-1.0.2`，长标题自动平衡换行；旧版 1.0.0 / 1.0.1 继续按原版式渲染。公共报告模板可通过结构化字段配置用途、确认依据、标题后缀与默认说明，发布后在报告创建时选择，内容固定到报告并计入摘要；数值与追溯表始终由核算快照生成。正式业务模板与规则引用签认在对外启用前补充。

集成测试会创建并删除一个独立的临时数据库。默认使用 `.env` 指定的 PostgreSQL 实例，可用 `TEST_DATABASE_URL` 指向独立测试实例。测试覆盖登录、管理员权限、A/B 学校切换、学校与账号页面、成员归属移除、账号删除、公共数据发布、密码重置、账号停用、模板数据项升级与校内审核、两校核算、运行幂等、输入版本冲突、证据授权、审核与旧结果冻结，以及报告编辑、独立审核、修订、历史预览、中文 PDF 一致性、并发导出、摘要篡改拦截和跨校下载隔离。测试结束删除临时数据库，截图和 PDF 验收产物放在临时目录，可用 `T07_ACCEPTANCE_OUTPUT_DIR` 指定位置。CI 运行格式、静态检查、单元测试、类型检查和构建。数据库集成测试需本地 PostgreSQL。

## 环境变量与部署

- `.env.example`：本地开发模板，包含 Compose 的 PostgreSQL 参数。
- `.env.test.example`：独立测试数据库模板。
- `.env.production.example`：生产连接和认证密钥示例。

`DATABASE_URL`、`BETTER_AUTH_URL` 和 `BETTER_AUTH_SECRET` 是运行必需变量。生产环境通过密钥管理器注入真实值，部署前执行 `npm run db:deploy`，再用 `npm run start` 启动 Node 服务。`/api/health` 报告进程健康；`/api/ready` 检查数据库与最新报告结构，未就绪返回 503。连接池上限和连接/空闲超时可配置，默认每进程 10 个连接。

PDF 运行环境需执行 `npm run pdf:install`；Linux 可用 `npx playwright install --with-deps chromium` 安装系统依赖。若部署使用预装浏览器，可用 `PDF_BROWSER_EXECUTABLE` 指定绝对可执行路径。字体与 OFL 许可已随 `public/fonts/` 提供，导出过程不访问外网。集成验收还需要 Poppler 的 `pdftotext`；本机受限环境可用 `npm run build -- --webpack` 完成生产构建。
